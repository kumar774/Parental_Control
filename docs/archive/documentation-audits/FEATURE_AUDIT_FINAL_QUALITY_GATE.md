## 2. In-Depth Technical Verification of `usb_adb_pairing`

A targeted forensic investigation was conducted across both competitor packages to separate and verify the two independent USB technical claims:

### Subsystem A: Android-to-Android USB-OTG ADB Activation
- **Parent-Side Entry**: `com.fundot.parent.androidusb.AdbActivateActivity`, `com.fundot.parent.androidusb.UsbReceiver`, declared in `AndroidManifest.xml` and layout `activity_adb_activite.xml`.
- **Child-Side Native Library**: `libadb.so` (90,392 bytes, compiled for ARM64/ARMv7 in KidsLink Child `lib/arm64-v8a/libadb.so`).
- **Child-Side Implementation Classes**: `moe.shizuku.manager.adb.AdbPairingClient`, `moe.shizuku.manager.adb.PairingContext`, `moe.shizuku.manager.adb.AdbPairingClient$a`.
- **Native Library Loading**: Traced in static constructor of `AdbPairingClient.smali`:
  ```smali
  const-string v0, "adb"
  invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;)V
  ```
- **JNI Methods Traced**: `PairingContext.smali` declares native JNI hooks: `nativeInitCipher`, `nativeEncrypt`, `nativeDecrypt`, `nativeDestroy`.
- **Execution Workflow**:
  1. Parent phone connects to Child phone using a USB-OTG adapter cable (`sc_need_connect`, `sc_usb_connect_prompt`).
  2. Parent `UsbReceiver` intercepts `android.hardware.usb.action.USB_DEVICE_ATTACHED`.
  3. Parent initiates local ADB socket handshake on port 5555.
  4. Child daemon executes privileged shell commands without a computer to grant `SET_VOLUME_KEY_LONG_PRESS_LISTENER`, `WRITE_SECURE_SETTINGS`, and seamless background permissions.
- **Evidence Classification**: `EXECUTION_PATH_IDENTIFIED` (KidsLink Child & Parent).

### Subsystem B: Android Parent-to-iOS Child Supervised Mode Provisioning
- **Parent-Side Entry**: `com.fundot.parent.iosusb.view.IosUsbActivity`, layout `activity_ios_usb.xml`.
- **Native Libraries**: `libiosusb_mux_test.so`, `libiosusb_pair_test.so`, `libiosusb_probe.so`, `libusb1.0.so` in KidsLink Parent `lib/arm64-v8a/`.
- **Native Bridge Classes**:
  - `com.fundot.parent.iosusb.nativebridge.IosUsbDevicePreflight`
  - `com.fundot.parent.iosusb.nativebridge.IosUsbMuxHandshake`
  - `com.fundot.parent.iosusb.nativebridge.IosUsbNativeProbe`
  - `com.fundot.parent.iosusb.nativebridge.IosUsbPairing`
  - `com.fundot.parent.iosusb.nativebridge.IosUsbRestoreExecutor`
  - `com.fundot.parent.iosusb.nativebridge.IosUsbServiceVerification`
- **String Resources**: Over 80 specialized strings (`ios_usb_title`, `ios_usb_status_not_connected`, `ios_usb_status_mux_starting`, `ios_usb_status_restore_running`, `ios_usb_disable_confirm_message`).
- **Execution Workflow**:
  1. Parent connects Android device to Child iPhone via lightning/Type-C cable.
  2. `IosUsbNativeProbe` checks USB host controllers.
  3. `IosUsbMuxHandshake` initializes a mobile usbmuxd tunnel talking to iOS MobileDevice services.
  4. Parent app generates local pairing payload and invokes `IosUsbRestoreExecutor` to push Apple Supervised Mode MDM profiles directly to the iPhone without requiring Apple Configurator on macOS.
- **Evidence Classification**: `EXECUTION_PATH_IDENTIFIED` (KidsLink Parent native bridge).
- **Limitations & Unknowns**: Testing profile deployment dynamically requires physical iOS device enrollment. Static native bridge and JNI signatures are completely mapped.

- **Evidentiary Finding**:
  - Parent UI Toggle: **VERIFIED**.
  - Child Teardown Logic: **VERIFIED**.
  - End-to-End Command Linkage: **INFERRED / UNVERIFIED WITHOUT LIVE NETWORK TRAFFIC**.
